# 本地工作看板 MVP 产品需求文档

版本：0.6 Rust 轻量桌面迁移（软件 v0.4.0）

日期：2026-11-03

适用平台：Windows

首批用户：个人自用，后续扩展至部门

本产品将每日检查、项目任务、定时提醒和工作流水集中到一个本地桌面工具中。用户可以提前安排例行事项，到点收到置顶提醒，处理后记录结果，并在汇报时按日期汇集工作素材。

MVP 不需要账号或服务器，业务数据仅保存在当前电脑。当前实现采用 Rust / Tauri、React、TypeScript 和嵌入式 SQLite，交付 Windows 当前用户安装包。复用已有界面和业务功能，通过系统 WebView2 显示界面，避免在安装包中重复携带完整浏览器。快捷键和提醒默认值可在后续使用中调整。

## 1 产品目标

1. 减少遗漏：每天或每周需要做的检查能按计划出现、到点提醒。
2. 降低记录成本：临时工作随手记一句，不强制填写表单。
3. 看清进展：集中查看项目状态、任务和最新进展。
4. 便于汇报：从工作流水和完成记录中整理日报、周报素材。
5. 降低配置成本：接收 Agent 生成的结构化配置，批量创建和更新事项。
6. 引导开发：按适合项目的路线推进，让新手明确当前目标、下一步和完成依据。
7. 管理协作：在本地记录责任、沟通结论、依赖和交接，不将文字记录伪装成在线派发或签署。

MVP 的核心验收流程：导入一周例行事项 → 关闭主窗口并驻留托盘 → 到点弹窗 → 处理并完成 → 记录工作结果 → 按周导出汇报素材。整个流程离线可用。

## 2 范围与边界

### 2.1 MVP 必须包含

| 模块 | 范围 |
| --- | --- |
| 今天 | 当日检查、一次性待办、逾期事项、工作流水快捷输入 |
| Checklist | 子检查项、一次性与重复安排、完成和跳过、历史记录 |
| 提醒 | 托盘驻留、置顶小窗、稍后提醒、启动与休眠恢复后的补提醒 |
| 项目 | 项目列表、普通任务看板、人工进度、最新进展；可选开发路线、目标、里程碑和开发任务 |
| 协作记录 | 参与人、责任边界、依赖、决策与变更、接口约定、交接状态 |
| 笔记与工作流水 | Markdown、本地保存、编辑、按日期查看、可选关联项目 |
| 汇报素材 | 日期筛选、预览勾选、去重、复制或导出 Markdown |
| Agent 配置 | JSON 粘贴与文件导入、字段校验、变更预览、批量新增与更新 |
| 数据管理 | 本地持久化、手动备份与恢复 |

### 2.2 MVP 不包含

- 账号登录、服务端部署、多端同步、多人同时编辑和真正的任务派发。
- 项目负责人远程查看、部门角色管理、公开分享链接。
- 内置大模型、模型 API Key、Agent 直接调用本地服务的接口。
- 自动读取运维平台、自动判断检查是否完成。
- 在线审批、跨项目依赖、甘特图、工时统计、附件托管和富文本协同编辑。

部门任务和开发协作均可在本机登记参与人、负责人和交接情况。人员是文字记录，不是登录身份；它不代表已经派发给其他人，也不触发对方通知。本地的接收和验收确认由当前操作者登记，不构成对方在线确认。

### 2.3 后续方向

后续加入服务器和账户鉴权后，个人笔记与例行事项默认仅本人可见，由本人主动决定是否公开；部门派发任务由执行人处理，对应项目负责人可查看完成结果。权限必须由服务端校验，负责人身份不自动授予访问私人笔记的权利。

第一版不展示无实际作用的“公开”开关。数据结构保留稳定标识和版本信息，为后续迁移留出空间，不提前实现同步协议。

## 3 典型场景

| 场景 | 操作与预期结果 |
| --- | --- |
| 每日运维检查 | 工作日 09:30 弹出提醒，打开任务检查告警、服务状态，记录异常后完成 |
| 临时工作记录 | 快捷键唤出输入框，输入“清理测试环境旧日志，释放约 20GB”，回车保存 |
| 项目推进 | 将项目任务从待办移至进行中，补充进展，更新项目进度 |
| 会议中收到提醒 | 选择稍后提醒，任务仍待处理，在指定时间再次提醒 |
| 周报整理 | 选择本周，查看流水和已完成任务，取消不需要的条目，复制 Markdown 给 Agent |
| 批量设置 | 将 Agent 生成的 JSON 粘贴进导入窗口，确认新增和更新清单后一次应用 |

## 4 信息架构

主导航设为“今天”“项目”“记录”，设置、导入和备份放在菜单中。

### 4.1 今天

- 顶部常驻“刚刚做了什么？记一句……”输入框。
- 待处理区域：到期提醒、今日待办和当日 checklist。
- 逾期区域：折叠显示之前尚未完成的事项，支持批量标记跳过。
- 已完成区域：显示当天完成和跳过的记录，两者分别统计。
- 今日工作流水：按记录时间倒序展示，提供编辑和删除。

任务卡显示标题、提醒时间、所属项目、状态和子项完成数。未设时间的当日事项可显示在今天，但不弹出提醒。

### 4.2 项目

项目详情包含状态、手动进度、最新进展和任务看板。看板只有“待办、进行中、已完成”三列；移动任务可通过菜单实现，拖拽不是首版验收前提。

项目关联的周期检查在独立区域展示，不将每天产生的检查记录堆入项目任务看板。

开发项目额外展示目标与路线、下一步、四列开发任务以及协作与交接记录。开发任务使用独立状态，不改变已有日历事项和周期检查的语义。已有项目可以主动启用开发流程；启用不重建项目、不删除普通任务或个人记录。

### 4.3 记录

提供“工作流水”和“普通笔记”两个页签。工作流水按日组织，可按日期、项目和关键词筛选；普通笔记按最近修改时间排列，可搜索标题和正文。

汇报素材入口位于工作流水页，使用日期范围生成预览。

## 5 功能需求

### 5.1 任务与 checklist

任务字段包含：标题、Markdown 描述、可选项目、可选负责人文字、日期、可选提醒时间、可选子检查项。标题必填，其余遵循最少输入原则。

支持一次性事项，以及每天、工作日、每周指定星期的重复事项。MVP 中工作日指周一至周五，不处理法定节假日调休。每周指定日期至少选择一天。

重复规则是模板，程序只生成运行当日应执行的独立记录，不补造未运行日期。唯一性由“模板标识 + 计划日期”保证，重启或重复计算不会重复生成。已经生成但未完成的记录保留为逾期。同一模板 MVP 每天最多安排一次；每天多次检查通过不同模板配置。

- 执行状态为待处理、已完成、已跳过；逾期是根据时间推导的显示状态。
- 子项可分别勾选，全部勾选后仍需明确点击完成，记录完成时间。
- 没有子项的任务可以直接完成；尚有子项未完成时，点击完成应提示并允许明确确认。
- 跳过保留历史记录，不计入完成数量；原因可选。
- 已完成或跳过的事项可以重新打开，记录变更时间，但不立即补弹旧提醒。
- 编辑模板会同步今天和未来尚未开始的执行记录；已经勾选子项、开始、完成、跳过、手动修改或选择稍后提醒的记录保留原快照。取消勾选不清除已开始标记。日期或重复规则改动不再适用的未开始实例撤销，不计作跳过。
- 暂停或归档模板停止后续生成和关联的未处理提醒，历史保留；恢复后从恢复当日开始，不补出暂停期间任务。

### 5.2 Windows 提醒

主窗口关闭默认隐藏到托盘；首次操作提示“程序仍在后台运行”。托盘提供打开看板、快速记录和退出。开机启动作为可关闭的设置项，建议默认关闭，由用户主动开启。

到点弹出置顶小窗，展示标题、项目、计划时间和子项摘要。小窗提供“打开任务”“10 分钟后提醒”“关闭”；完成操作在任务详情中进行，避免误触。

建议默认行为：

- 弹窗位于其他普通应用窗口上方，不主动夺取键盘焦点。
- 关闭弹窗仅表示本次已看过，任务仍待处理，不自动反复弹出。
- 稍后提醒只调整当前执行记录的下一次提醒时间，不改变重复模板。
- 同时到期的多条事项合并成一个提醒列表，避免逐个弹窗。
- 完成、跳过或暂停后，取消对应尚未触发的提醒。
- 应用退出、电脑关机或休眠期间无法弹窗；应用启动或恢复后重新核对待提醒事项。
- 只对当天漏发提醒合并补弹一次；以前日期的未完成事项放入逾期列表，不连续补弹。用户明确设置的跨日稍后提醒按指定时间执行。
- 同一次提醒保留触发与已读记录，正常重启后不再次重复弹出；选择稍后提醒的事项除外。

日期与提醒默认采用 Asia/Shanghai。MVP 不支持每条任务使用不同的时区。系统锁屏、安全桌面以及某些独占全屏场景不保证置顶显示，回到正常桌面后应能查看待处理提醒。

### 5.3 项目进度

项目包含名称、说明、负责人文字、状态、进度百分比和最新进展。名称必填，进度范围为 0 至 100，状态为未开始、进行中、暂停、已完成。

进度由用户手动更新，不按例行检查的完成率推算。状态与进度不强制联动；例如进度到 100 后仍需用户确认项目状态。

项目可关联普通任务、周期检查及工作流水。更新项目进展时可选择同步保存一条工作流水，默认不自动生成。项目归档后不在默认列表显示，相关记录继续保留。

### 5.4 工作流水

工作流水面向“刚刚做了什么”的低成本记录，正文必填，项目可选，时间自动填入。保存时不要求标题或标签。

- 首页和全局快捷键均可唤出输入框；建议快捷键为 Ctrl+Alt+J，可修改，冲突时提示重新设置。
- Enter 保存，Shift+Enter 换行；中文输入法组合文字期间的回车不得触发保存。
- 支持 Markdown 文本，保存后立即可见；写入失败时保留输入，提示重试。
- 支持修改正文、关联项目和归属日期，以便补记昨天的工作；实际创建及修改时间仍单独保留。
- 任务完成后可选填处理结果，保存为关联该执行记录的工作流水；不填写也可完成。
- 删除需确认；原任务的完成记录不会因流水删除而改变。

### 5.5 普通笔记

普通笔记用于长期备忘，支持标题、Markdown 正文、创建与修改时间，以及可选项目关联。支持新增、编辑、搜索和删除；不提供附件或所见即所得编辑器。

笔记可通过“创建关联提醒”生成一次性任务，任务链接回笔记。笔记本身不承担任务状态和重复调度逻辑。

所有记录仅存本地，但这不等于应用级加密：MVP 不提供独立密码或数据库加密，访问依赖当前 Windows 用户和文件权限。

### 5.6 汇报素材

提供今天、本周和自定义日期范围，本周默认周一至周日。筛选口径：流水使用归属日期，完成任务使用完成日期；日期范围包含首尾两天。

默认收集工作流水和已完成任务。普通笔记、跳过事项及未完成任务不默认进入素材；用户可额外选择待跟进事项。导出前逐条预览和勾选，支持按日期或项目分组。

同一执行记录的完成信息与关联处理结果合并成一个条目；不同日期的重复检查仍是独立记录。不基于文本相似度擅自删除记录。

支持复制和导出 UTF-8 Markdown，保留日期、项目、任务标题及原文。MVP 只整理事实素材，不自动生成结论或补写成果。用户可以交给外部 Agent 总结，产品内不自动发送任何内容。

### 5.7 Agent 结构化配置

支持粘贴 JSON 和选择本地 JSON 文件。首版导入对象为一次性任务和重复 checklist，项目必须预先存在；笔记、项目和历史完成记录暂不通过该入口创建。

导入流程：解析 → 完整校验 → 显示新增、修改和未变化的条目 → 用户确认 → 一次性提交。任意条目无效时整批不写入，错误定位到条目和字段；用户修正后重新导入。

稳定的外部 id 用于匹配更新。相同 id 导入相同内容不产生重复记录；更新同步今天及未来未开始的执行记录，已操作记录、完成历史和工作流水保留。预览显示受保护记录数量；预览后数据或日期变化时重新预览。导入未出现的既有事项保持不变，不支持通过导入删除。

建议 v1 格式示例：

```json
{
  "schema_version": 1,
  "items": [
    {
      "id": "daily-ops-check",
      "type": "checklist",
      "title": "检查运维状态",
      "project_id": null,
      "content_markdown": "检查后如有异常，请记录处理情况。",
      "checklist": [
        { "id": "alerts", "text": "查看告警" },
        { "id": "services", "text": "检查服务状态" }
      ],
      "schedule": {
        "frequency": "weekdays",
        "start_date": "2026-10-28",
        "time": "09:30",
        "timezone": "Asia/Shanghai"
      },
      "reminder": {
        "popup": true,
        "snooze_minutes": 10
      }
    }
  ]
}
```

| 字段 | v1 约定 |
| --- | --- |
| schema_version | 必填，仅接受 1；不支持的版本拒绝导入 |
| items | 必填非空数组；建议单次最多 500 条 |
| id | 必填，应用内外部标识唯一；同批重复 id 为错误 |
| type | task 或 checklist；task 不含子项，checklist 至少有一个子项 |
| title | 必填，去除首尾空白后 1 至 200 字符 |
| project_id | 可空；非空必须引用当前本地已有项目 |
| content_markdown | 可省略，默认空文本 |
| checklist | 子项 id 在条目内唯一，text 非空；不接受完成状态 |
| schedule.frequency | once、daily、weekdays、weekly |
| schedule.date | once 必填，YYYY-MM-DD |
| schedule.start_date | 重复事项必填，YYYY-MM-DD |
| schedule.weekdays | weekly 必填，1 至 7 表示周一至周日，不可重复 |
| schedule.time | 可省略；提供时为 24 小时制 HH:mm |
| schedule.timezone | 可省略，默认 Asia/Shanghai；v1 不接受其他值 |
| reminder.popup | 默认 false；true 时必须提供 time |
| reminder.snooze_minutes | 默认 10；正整数，建议范围 1 至 1440 |

v1 采用完整配置替换语义：同 id 的可选字段省略时恢复为默认值，预览必须展示字段清空情况。未知字段拒绝并提示，避免配置看似成功但未生效。清单子项以 checklist 为准，Markdown 内的任务框只是正文，不重复生成检查项。

首次导入的重复任务从不早于当天的有效日期生成，不补造过去的检查记录。一次性任务日期在过去时可导入并显示逾期，预览中明确提示。

应用提供样例、字段说明及导出现有事项配置的入口，让用户将配置交给 Agent 修改后重新导入。公开发布、外部命令、脚本执行和文件路径写入不属于该格式能力。

### 5.8 数据备份与恢复

所有业务数据保存至当前 Windows 用户的应用数据目录，不写在安装目录。使用 SQLite，正式数据库路径为 `%APPDATA%\Kanban\kanban.db`。Rust 版沿用原 Electron 版的数据表结构与备份格式，升级不得重建为空白库或静默丢弃旧数据。

支持将完整业务数据导出为带格式版本的备份文件，包含任务模板、执行记录、项目、流水、笔记及用户设置。备份应取得一致快照，不能直接复制写入中的数据库文件作为唯一实现。

恢复前校验版本和内容完整性，展示备份时间及数量。MVP 采用全量替换，不做合并；用户确认后先备份当前数据，再事务性恢复，失败时保持原数据可用。安装升级须保留已有数据，迁移前自动备份。

### 5.9 开发流程与协作

提供六种预置路线：新手带做、原型验证、敏捷迭代、持续看板、阶段交付、限定投入。协作方式独立选择个人、小组、跨部门；引导程度独立选择详细或简洁。个人迭代模式参考 Scrum，不宣称是具备完整角色和事件的 Scrum 实施。

所有路线使用相同的目标、范围、暂不做内容、验收标准、里程碑及开发任务对象。路线决定引导内容；切换路线保留已有里程碑、任务、证据和沟通记录。原型验证的结束意味着完成想法验证，不能直接等同于软件已交付。

新手指引应解释当前步骤的行动、示例、完成条件和卡住后的处理。默认突出最多三个可执行任务：优先继续已开始任务，依赖未完成或有阻碍的任务不能作为可开始任务；当前里程碑和优先级影响排序。无可执行任务时说明需要补充目标、拆任务或解除阻碍。

里程碑保存目标、验收标准、可选目标日期、状态和验证证据。关联任务全部完成且留下证据后才能标记里程碑完成。任务完成率与里程碑验收数分别展示，不将任务数量比例冒充项目交付百分比。可设置同时进行的任务上限，超出时引导先完成在做事项。

开发任务使用“待开始、进行中、待验收、已完成”四种状态，可记录优先级、依赖和阻碍。任务包含一名主要负责人、协助人、验收人、接收人，以及输入、负责范围、输出和验收条件。依赖必须引用同一流程中存在的任务，禁止自依赖和循环。标记完成需要验收标准、结果证据且所有依赖已经完成。

协作记录包含待确认/已确认的决策、需求变更及接口约定。记录话题、相关人员、结论、影响、日期和可选跟进日期。接口约定可写明输入、输出、格式样例、异常处理、联调安排和变更联系人。跟进事项可通过已有事项表单创建定时提醒，仍遵循原有提醒规则。

交接包包含交付物与版本、使用说明、验证结果、已知问题、后续行动和补充说明。状态区分准备、已提交、已接收、验收通过、退回补充。存在接收人的任务必须记录交接验收通过后才可标记完成；接收确认不等于验收通过。

Agent 任务说明仅导出本项目开发流程中的上下文。流程 JSON 使用独立格式，导入前校验并预览，确认时检查数据版本，变更后必须重新预览。条目按稳定 id 合并，未出现的原有条目保留；已开始、有证据或有交接记录的任务及已完成里程碑受到保护。Agent 声称已完成的新任务先进入待验收，交接声明最多登记为已提交，避免冒充人工验收。它与原有事项 `schema_version: 1` 格式分开，不能混用。

开发任务完成后将结果记入项目工作流水，重新完成同一任务不重复生成流水。开发配置和 Agent 说明不自动包含普通笔记。所有复制和导出由用户操作，用户自行向外部 Agent 或协作人发送。

保存和导入需通过主进程校验，使用数据版本防止旧页面覆盖新数据。保存失败保留草稿，明确提示重新载入后再处理冲突。现有项目 JSON 扩展保存可选流程，旧数据无需批量重写，流程随项目一起备份恢复。应用版本变化且数据库已有内容时，在提供窗口操作之前自动备份；备份失败则停止启动，不提前改写版本标记。旧版本不支持新版开发流程，降级时应使用升级前备份。

详细路线与使用规则见 [开发流程使用说明](WORKFLOWS.md)。

## 6 数据对象与关键约束

| 对象 | 主要信息 | 关键约束 |
| --- | --- | --- |
| 项目 | id、名称、状态、进度、负责人文字、最新进展 | 归档不删除历史 |
| 任务模板 | id、external_id、标题、类型、规则、项目、子项 | external_id 唯一；暂停停止生成 |
| 执行记录 | id、模板 id、计划日期、内容快照、状态、完成时间 | 模板与计划日期组合唯一 |
| 提醒记录 | 执行记录 id、计划触发时间、稍后时间、触发及已读状态 | 重启后可恢复，完成后取消 |
| 工作流水 | id、正文、归属日期、创建及修改时间、项目、可选执行记录 id | 独立记录或关联任务结果 |
| 普通笔记 | id、标题、正文、项目、创建及修改时间 | 不默认进入汇报素材 |
| 开发流程 | 路线、协作方式、目标、范围、验收、参与人 | 可选，随项目保存；不建立虚假账号 |
| 里程碑 | id、目标、验收、状态、证据 | 关联任务完成且有证据后可完成 |
| 开发任务 | id、责任、依赖、状态、证据、交接包 | 禁止循环依赖；完成需满足依赖与验收规则 |
| 沟通记录 | id、类型、话题、相关人、结论、影响、跟进日期 | 本地登记确认，不代替在线签署 |

普通项目任务使用待办、进行中、已完成状态；检查执行记录使用待处理、已完成、已跳过状态。两类状态不强行共用枚举。

对象使用稳定标识，日期与绝对时间分别保存。重复计划使用本地日期和时区，完成及创建时间保存为可还原的绝对时间。暂不建立虚假的多用户身份或权限表。

## 7 非功能需求

### 桌面便签与界面状态

提供独立常驻小便签，默认约 380×560，标题栏可拖动，窗口可在 340×420 至 560×900 范围调整（受屏幕工作区限制）；默认置顶，可取消。事项标题和检查子项完整换行，内容多时内部滚动，不省略检查内容。显示当天仍需处理的 checklist 及子项，勾选直接写回同一执行记录；勾完后到事项详情确认结果与完成，不自动代替业务验收。下方按时间列出最近两条提醒，使用已设置的稍后时间，并可预览未来的重复计划；预览本身不生成未来执行记录。

主窗口和托盘均可打开便签，关闭便签只隐藏。记住上次显示、置顶、大小和位置；屏幕变化后将便签放回可见工作区。刷新数据和自动恢复显示不抢键盘焦点。便签使用专用数据接口，不读取私人笔记、完整项目或汇报数据。

项目开发工作台默认折叠，每个项目独立记住展开状态。折叠保留正在编辑的内容，不取消已有的离开页面草稿保护。统一使用约 120–180 毫秒的颜色、淡入与折叠反馈，无额外延迟；系统要求减少动态效果时禁用位移及折叠动画。

“今天”页提供二级“日历回顾”，保留三个主导航。日历按北京时间、周一至周日显示月份；选择日期后列出该日的实际事项与按归属日期记录的工作流水，可打开详情、补记工作和新增安排。过去未运行的周期日期保持空白，不补造历史；将来日期可以显示已有模板推算的计划，明确区分计划和执行记录。已有记录优先采用当次快照，不被当前模板覆盖；已撤销实例不显示，暂停或归档的模板不生成计划预览，历史实际记录仍可回顾。点击计划进入配置编辑，点击实际事项沿用原有处理和重新打开功能。

- 核心功能完全离线；未经用户操作不发送笔记、工作流水或任务到外部服务。
- 发布包包含 Rust 原生程序和前端资源，最终用户无需 Node.js、Rust 或开发工具。运行依赖系统 WebView2 Runtime；已有运行时时可离线安装，缺少时安装程序联网补装，分发说明必须明确此条件。
- 轻量化不缩减已有功能。记录实际安装包大小，明确不含系统共享运行时，不能把开发目录体积或运行时下载量混为安装包大小。
- 保留原数据位置、Agent 配置和备份格式。跨桌面框架迁移需先导出备份、通过托盘退出旧程序，再卸载旧版并安装新版；默认保留业务数据，不手动删除 AppData 数据目录，新版自动读取原数据库。安装器不自动卸载旧 Electron 版，明确此流程以避免重复安装登记。数据兼容、迁移安装和后续 Rust 版之间的覆盖升级分别验证、分别报告；首版 Rust 包仍采用手动安装升级。
- 同一 Windows 用户只运行一个应用实例，避免双重提醒和重复写入。
- 保存成功提示必须发生在本地提交成功之后；失败保留用户输入。
- Markdown 预览不执行内嵌脚本，默认不自动加载远程图片；外链由用户点击后打开。
- 建议性能目标：普通办公电脑上 1 万条工作记录可正常搜索与浏览；冷启动 3 秒内可操作、常规保存 300 毫秒内反馈。开发验收时记录实际测试机器和结果。
- 提醒精度建议目标：应用运行、电脑唤醒且未锁屏时，在计划时间后 10 秒内出现；休眠期间不作准时保证。
- 中文输入、长文本、显示缩放与多显示器环境下，关键按钮和弹窗内容可访问。

| 阶段 | 交付结果 |
| --- | --- |

各阶段均属于本 MVP，不单独扩大范围。先用个人真实例行事项试用一周，重点观察遗漏提醒、记录步骤是否过多、汇报素材是否完整，再决定是否启动部门协作版本。

## 10 开发前可调整的默认项

以下不是启动开发的阻塞项，可按本文默认值实现后通过试用调整：

## 11 后续体验与 AI 填写需求（2026-11-04）

本节记录后续需求，交付状态见实施计划。

### 11.1 动画体验

用户反馈当前交互动画不足。统一完善页面及标签切换、开发工作台展开收起、弹窗进出、清单勾选反馈和列表增删过渡。动效柔和、短促，优先沿用 120–180 毫秒节奏，操作立即响应，避免等动画结束才能继续操作。支持系统减少动态效果偏好，快速连续操作时状态和焦点正确。

### 11.2 所有填写项支持 AI 结构化填写

目标是让用户把需求描述交给外部 AI，由 AI 生成结构化文件，经应用预览导入后完成表单填写。覆盖全软件可编辑业务字段，包括截图中的项目目标、本次交付范围、暂不做内容、项目验收清单，以及里程碑、开发任务、协作交接、日期事项、检查子项、提醒、工作流水和笔记。可配置设置同样纳入字段盘点，逐项明确可导入方式及应用影响。

复用已有项目、开发流程和事项导入能力，补齐尚未覆盖的表单。每种表单提供同源 Schema、完整模板、字段说明和当前内容导出，支持新建与更新。用户可复制当前表单上下文给 Agent，拿回文件或粘贴内容后看到字段变化、清空及受保护记录，再确认应用。保留稳定 ID、严格校验、事务提交和过期预览检测。

空白信息允许 AI 标记待确认。实际完成、验收、接收等事实必须带有用户提供的依据并沿用现有确认规则。私人笔记和流水仅在用户选择对应内容时进入导出上下文。每个可编辑字段都要有覆盖记录，系统生成的 ID、创建时间及计算结果在契约中明确标为系统维护。

后续规划软件内 harness，承接上下文整理、模型调用、工具执行及结果确认。现阶段以外部 Agent 和结构化导入作为填写入口。
