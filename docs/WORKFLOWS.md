# 开发流程与本地协作

本页说明 v0.2.0 开发项目功能及 v0.2.1 完整项目配置导入。它帮助个人组织开发并记录合作情况；核心功能离线运行，没有账号、服务器、内置模型或在线共同编辑。

从 v0.3.0 起，项目中的“开发工作台”默认收起。需要使用时点击“展开开发工作台”；每个项目分别记住上次选择。收起只隐藏内容，尚未保存的修改仍保留，离开项目时继续提示处理草稿。

## 让 Agent 一次填好项目表单

完整项目配置可同时填写项目基本信息和全部开发流程字段。项目页点击“Agent 填写项目”可创建项目；当前项目的“导入 / 导出项目信息”用于导出、更新。选择 JSON 文件或粘贴内容后，先“校验并预览”，再确认填入软件。

新项目可以先保存模板文件，和项目描述一起交给 Agent。修改已有项目则先导出该项目配置，让 Agent 保留已有 id 后修改。填写指南、可复制提示和完整字段表见 [Agent 填写指南](../examples/PROJECT_AGENT_GUIDE.md)；机器约束见 [项目 Schema](../examples/project.schema.json)。

格式为 `schema_version: 1`、`kind: "kanban-project"` 和 `project` 对象。`project` 包含名称、说明、负责人、状态、进度、最新进展、归档，以及可选 `workflow`。开发流程中的目标、范围、参与人、里程碑、任务、沟通和交接均可在文件中编辑。

没有项目 id 的文件从全局入口确认后创建新项目；从已有项目入口打开时，省略 id 表示当前项目。明确填写其他项目 id 会被拒绝。更新基本信息时省略可选字段会恢复默认值，预览显示前后变化；已有项目省略开发流程则保持原样。

流程按条目 id 合并，保留文件未出现的记录，并保护已操作任务、已完成里程碑和已确认沟通。Agent 自报完成的新任务进入待验收，接收与验收仍需依据实际沟通登记。确认前数据发生变化时需要重新预览。

这份配置只负责填项目表单，不包含普通笔记、工作流水、日期事项、周期检查和应用设置；需要搬迁所有数据时仍使用完整备份。流程中显式填写的人员联系方式和交付物位置会导出，请先查看内容。旧的单独开发流程和日期事项配置继续保留原入口。

## 选择路线

| 路线 | 适合情况 | 路线意图 |
| --- | --- | --- |
| 新手带做 | 第一次做项目，需要每步有具体说明 | 从真实问题、首版范围走到可运行版本、验证交付和反馈 |
| 原型验证 | 不确定需求或产品样子 | 验证一个关键问题；结束后再决定是否正式开发 |
| 敏捷迭代 | 需求经常变化，希望按周期交付 | 每轮有一个可演示目标，按反馈调整下一轮 |
| 持续看板 | 程序已经能用，随时修问题和加功能 | 先完成正在做的事项，控制同时开工数量 |
| 阶段交付 | 需求和验收要求比较清楚 | 按明确的阶段结果推进，记录范围变更 |
| 限定投入 | 功能容易膨胀，迟迟无法收尾 | 先约定投入与必须交付的结果，再裁减非必要内容 |

协作方式与路线分开：任何路线都可选择个人、小组或跨部门。详细引导适合新手，简洁引导适合已熟悉流程的人。个人敏捷模板参考 Scrum，但不替代完整的 Scrum 角色、事件和规则。

切换路线保留已有目标、里程碑、任务、证据和沟通记录；它不会按新模板清空项目。需要新一轮迭代时新增里程碑，并为本轮明确一个可验收结果。普通任务和周期检查仍在项目中保留。

## 从第一步开始

1. 描述目标：谁在什么场景下，用软件解决什么问题。
2. 写清本次范围和暂不做内容。先选一个从输入到结果的完整流程。
3. 为当前里程碑写下验收条件，例如“关闭主窗口后，定时提醒仍能出现”。
4. 进入当前步骤，查看行动、示例、完成依据和卡住后的处理方式。
5. 添加少量能立即开始的任务，写清每个任务的结果和验证办法。
6. 记录实际结果并验收；完整交付还要检查安装、启动和数据保留，不能只凭代码已生成就判断完成。

页面提供下一步建议，优先继续已开始且未受阻的工作。依赖未完成或有阻碍的任务不能当成可立即开始的任务。推荐只是本地规则，可根据项目实际安排处理顺序。

里程碑可以填写目标日期，用于安排本轮交付；它是计划日期，不是系统预测的工期。流程可设置同时进行的任务上限，达到上限后先完成在做工作，再启动下一项。新手通常从一次一项主要任务开始。

## 开发任务和完成依据

开发任务有待开始、进行中、待验收、已完成四种状态。普通日期事项和周期检查继续使用原有状态。开发任务不会按天复制。

- 一个任务填写一名主要负责人，可补充协助人、验收人和接收人。
- 记录“需要别人给什么”“我负责到哪里”“交出去什么”，减少口头分工的空隙。
- 依赖只能选择同一流程的已有任务，禁止自依赖和循环。
- 完成任务需要验收条件和结果证据；依赖的任务应先完成。
- 有接收人的任务，还需要交接状态为验收通过。
- 完成里程碑需要结果证据及其关联任务全部完成。
- 同一开发任务首次完成时记录工作流水，重新完成时更新该结果记录，避免汇报重复。

任务完成率是数量比例，不代表整个软件已交付。里程碑验收数、结果证据和实际安装试用情况应分别查看。

## 沟通、接口和变更

参与人记录姓名、角色与联系方式，便于知道该找谁。该记录不建立账号，也不向别人开放本机数据。

沟通分为决策、需求变更、接口约定。记录问题、相关人、结论、影响、确认情况和可选跟进日期。尚未达成一致就保持待确认；本地的已确认表示你根据实际沟通进行了登记。

接口约定可以写成：输入是什么、输出是什么、格式和样例、出错怎么处理、什么时候一起验证、变更先通知谁。接口也可以是设计稿、Excel 或安装包，不局限于程序 API。

变更记录应说明本次范围、时间和已完成工作受到什么影响，再决定纳入本次还是推迟。应用记录这些结论，不替团队做审批。

跟进日期用于安排回访。创建提醒时进入原有事项表单，确认日期和提醒时间后保存；这个提醒是独立日期事项，处理后仍需在相应记录中登记沟通或交接结果。

## 交接

交接状态为：准备、已提交、已接收、验收通过、退回补充。

已提交表示交出了材料；已接收表示对方能找到并理解材料；验收通过表示结果符合标准。它们是不同事实，应按实际情况记录。退回时写明要补充什么，再更新交接包。

交接包包含：

- 交付物及版本，例如安装包名称、代码版本或文档位置。
- 使用、启动或接手说明。
- 已验证的场景和验证结果。
- 已知问题、限制和风险。
- 下一步与后续负责人，以及补充说明。

本版只保存文字，不托管文件、不管理下载权限，也不发送消息。交付物位置和内容应由协作双方自行确认可访问。

## 与外部 Agent 配合

在流程中预览 Agent 任务说明，再复制给所用的 Agent。说明包含项目目标、范围、任务、责任、依赖、验收和需要返回的结果，不自动读取普通笔记。

流程 JSON 使用自己的格式与导入入口，与日期事项的 `schema_version: 1` 配置分开。建议先导出现有流程，让 Agent 保留稳定 id 后修改，再预览导入。流程条目按 id 合并，未出现的原有条目保留。已开始、有证据或有交接记录的任务及已完成里程碑受到保护，预览说明保护结果。Agent 声称已完成的新任务进入待验收，交接结果最多登记为已提交，真实接收与验收由用户确认。

导入和保存都在主进程进行校验。预览之后若数据发生变化，确认会被拒绝，需重新载入并重新预览。保存失败保留草稿；重新载入前应自行复制需要保留的内容。

导出内容可能包含参与人、项目决策和交付物位置，请在发送前查看预览。应用不自动上传或发送数据，也不把“Agent 说已实现”当成真实验收通过。

完整样例见 [开发流程示例](../examples/development-workflow.json)，JSON Schema 见 [流程结构](../examples/workflow.schema.json)。样例中的 `project_id` 必须替换成你实际项目的导出 id；不要把样例里的项目占位符当成真实项目。使用 `npm run schema:workflow` 可从共享契约重新生成样例和 Schema。

## 备份和兼容

旧项目没有开发流程时仍正常使用。开发流程是项目的可选数据，随项目一起进入完整备份与恢复。项目归档保留流程和结果。流程 JSON 适合配置交换，完整迁移仍应使用设置中的备份功能。

应用检测到版本变化且已有业务数据时，在启动窗口前将完整数据库快照保存到数据目录的 `backups/before-upgrade-<版本>-<时间>-<唯一标识>.kanban-backup`。同版本启动不会重复备份；新建空数据库不需要升级备份；备份失败会停止启动并保留旧版本标记。v0.1.0 不理解开发流程，不能直接用它编辑 v0.2.0 数据；需要降级时先另存当前备份，再使用升级前的备份。

以下资料是方法参考，本应用提供适合本地个人使用的简化模板。

- Kanban 强调明确工作流、控制在制工作和改善流动：[Kanban Guide，2025 年 5 月版](https://kanbanguides.org/the-kanban-guide)。
- 通过原型验证关键假设：[Google Design Sprint](https://designsprintkit.withgoogle.com/methodology)、[Lean Startup](https://theleanstartup.com/principles)。
- 限定投入、塑造范围及按团队规模适配：[Shape Up](https://basecamp.com/shapeup/4.1-appendix-02)。
- 规格、设计和任务驱动 AI 开发：[GitHub Spec Kit](https://github.github.com/spec-kit/reference/agentic-sdd.html)、[Kiro Specs](https://kiro.dev/docs/specs/)。
