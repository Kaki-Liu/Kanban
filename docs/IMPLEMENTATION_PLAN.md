## 已确认的决策

- 当前 v0.4.0 使用 Rust / Tauri、React、TypeScript 和嵌入式 SQLite，替换此前 Electron 桌面运行层；Windows 11 x64 本地使用。可登记多人协作情况，不提供在线共同编辑。
- 周期事项只生成当天记录，不补未运行日期。
- 同 id 配置更新同步未开始的今天及未来实例，已操作记录保留。
- Windows 当前用户安装包，无账号、网络服务或内置模型。
- 安装包复用系统 WebView2 Runtime；已具备运行时时支持离线安装，缺少时联网补装。用户无需安装开发工具。

## 具体实现规则

主进程每 5 秒检查提醒，监听恢复和解锁。配置与执行记录分别保存；执行记录以配置 id 和计划日期唯一。提醒状态持久化，关闭不完成，稍后提醒仅改本次。

首次勾选子项、任务开始或保存结果即记录开始时间，取消勾选也不清除此时间。手工修改本次内容或选择稍后提醒的记录同样受保护。未开始实例若不再符合更新后的计划，标记撤销，避免当作跳过统计。

导入预览绑定数据版本和日期；提交前变化时要求重新预览。批次使用数据库事务。备份调用 SQLite backup API；恢复前校验固定表结构、版本、数据和关联，自动备份当前数据后在事务中替换。

## v0.4.0 Rust 轻量桌面迁移

本轮目标是缩小部门分发包，保留既有业务与界面，不裁掉功能。复用 React 页面、类型契约和现有 SQLite 表结构，将业务、持久化、提醒及桌面系统接口迁入 Rust / Tauri。正式包不包含 Electron、Node.js 或完整 Chromium，使用系统共享的 WebView2。

| 阶段 | 内容 | 验收重点 | 状态 |
| --- | --- | --- | --- |
| R0 | Tauri 构建、原生桌面边界、共享前端 | 现有页面可操作，正式包不含开发工具 | 已实现，GNU Windows x64 构建及 NSIS 打包完成 |
| R1 | Rust 存储与业务规则 | 当天实例、保护更新、提醒状态、汇报去重、日期与依赖校验一致 | 已实现，Rust 业务测试及与旧实现的数据对照通过 |
| R2 | 原生窗口、托盘、快捷键及调度 | 主窗口隐藏后驻留、便签同步、提醒展示、单实例与退出 | 已实现，WebView2 界面回归与桌面检查结果见验收记录 |
| R3 | Agent 配置与备份迁移 | 严格校验、过期预览、事务回滚、旧数据与备份互通 | 已实现，配置及双向备份兼容验证通过 |
| R4 | 轻量分发、开发说明与版本管理 | 明确运行时条件、数据路径和实际包体积 | 安装包已生成；安装及升级的实测范围见验收记录 |

正式数据继续保存到 `%APPDATA%\Kanban\kanban.db`，不搬入安装目录。迁移顺序为：导出备份、从托盘退出旧 Electron 版、卸载旧版、安装并启动 Rust 版。卸载默认保留业务数据，不手动删除 AppData 中的 Kanban 目录；新版自动读取原数据库，并执行版本变更前的自动备份。两个框架的安装登记不同，新安装器不自动卸载旧程序，这一步骤避免遗留两份安装登记。数据格式兼容已经验证，完整卸载及迁移安装过程尚未实机验证。后续 Rust 版本使用同一 NSIS 安装体系覆盖升级，数据保留仍需在版本发布时实测，不沿用旧 Electron 结论。离线安装的前提是电脑已有 WebView2，缺少运行时的安装会联网下载。

原 Electron 实现作为迁移对照保留在源码中，默认开发、构建和发包入口已改为 Tauri。校验契约通过 `schema:rust` 生成 Rust 使用的 Schema，前端构建入口也会自动生成；`test:harness` 构建独立数据对照程序 `store-probe`，它不进入生产安装包。标准 Windows 开发环境为 Rust MSVC 与 C++ Build Tools，本次实际构建采用 GNU / GCC，具体命令见 [README](../README.md)。真实测试、包体积和未实测事项统一见 [版本验收记录](VERIFICATION.md)。
